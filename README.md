# renrengame

一个 2.5D 网页多人在线游戏（MMO）的原型：浏览器里用 3D 模型加固定斜俯视角渲染，所有玩家连到同一个权威服务器，在同一张大地图上移动、打怪并互相看到。

目前有“登录、进入世界、点击移动、看到附近的玩家、打怪、捡金币、药水和武器、装备武器、找商人买卖、死亡复活”这一条主线，没有玩家对战、经验等级、技能、聊天等玩法。装备只有武器一个栏位，武器只有一种，商人也只卖药水和这一种武器。

## 已有的功能

- **画面**：Three.js（WebGL 2）渲染，固定斜俯视角镜头跟随角色，带骨骼动画的人物模型，头顶有名字和血条。玩家有男女两种模型，性别、肤色、发色和上衣颜色由名字决定，同一个人每次上线都是同一个样子。
- **移动**：点击地面移动，按住可以连续移动，滚轮缩放。服务端寻路并绕开障碍物。
- **手机**：手机浏览器里可以直接玩，所有操作都有按钮。单指点和按住是移动，双指捏合调镜头远近；竖屏时镜头会自动拉远一些，横屏时背包和商店左右并排。
- **声音**：出拳、挥剑、挨打、怪物和玩家倒下、复活、捡金币和物品、喝药水、换武器、买卖、脚步和面板开关都有声效。别人打怪的声音按距离变小，并且偏向它在画面上的那一侧。点左上角的“音效”或者按 M 开关，选择会记住。
- **战斗**：点击怪物后角色自己走过去，站定后自动攻击，直到怪物死亡或者点了地面。空手时出拳，拿着剑时挥剑，命中时有受击闪烁和伤害数字。
- **怪物**：地图上有 120 只怪物（行尸：灰绿色皮肤、光头、红眼睛的人形）。玩家走近或者打了它，它会追上来攻击；被带离出生位置太远时放弃，回满血走回去，回去的路上不受伤害；死后 20 秒在原地重生。几只怪物追同一个玩家时会并排走、围着玩家散开站，不会叠成一只。
- **掉落和拾取**：怪物死后在尸体旁边掉一堆金币（3–8 个），有四分之一的机会再掉一瓶治疗药水，有 5% 的机会掉一把青铜剑。走到物品旁边就自动捡起来，也可以点地上的物品让角色自己走过去；掉落不分是谁打的，先到先得；60 秒没人捡就消失。
- **药水**：按数字键 1 或者点左上角的药水按钮喝一瓶，回 40 点血，之后 5 秒内不能再喝，刚上线时也要先等 5 秒。最多带 20 瓶，带满了地上的药水捡不起来。
- **武器和背包**：按 B 或者点左上角的“背包”打开背包面板，上面是武器栏和现在的攻击力，下面是背包里的东西。点背包里的剑把它拿到手里，点武器栏把它收回背包；捡到武器不会自动装备。空手一拳 12 点伤害，拿着青铜剑一下 20 点。剑拿在手上，别的玩家也看得到。背包里最多放 5 把剑，手里那把不算在内。
- **商人**：安全区里站着一个商人（脚下有一块红色的地毯）。点他，角色自己走过去，到了跟前商店面板自动打开，走远了自动关上，也可以按 Esc 或者点 × 关上。药水 15 金币一瓶、青铜剑 100 金币一把；多余的药水和剑可以卖给他，药水 5 金币、剑 25 金币。点一下买卖一个，按住 Shift 点一下是 5 个。拿在手里的剑要先收回背包才能卖。
- **安全区**：出生点周围半径 14 的范围（地上有一圈浅色的线）。怪物不会进去，也不会攻击里面的玩家。
- **死亡和回血**：血量归零后倒地，5 秒后在出生点满血复活，背包里的东西和手里的武器都不会掉。倒地的时候不能换武器。6 秒没有打人也没有挨打，开始慢慢回血。
- **同步**：服务器每秒模拟 20 次、下发 10 次快照；自己的角色本地预测，其他玩家用快照插值。
- **视野**：256×256 的地图按 32×32 分格，每个玩家只收到自己所在格和周围 8 格内的实体。
- **账号**：注册、登录，7 天内免密码进入；同一账号在别处登录时旧连接被顶下线。
- **存档**：角色的位置、血量、背包和手里的武器在下线时、每 30 秒和服务器关闭时写进数据库。死亡状态下线的角色，下次上线时在出生点满血复活。

## 技术栈

| 部分 | 用的东西 |
|---|---|
| 客户端 | TypeScript、Three.js、Vite |
| 服务器 | TypeScript、Node.js、`ws`，用 `tsx` 直接运行 |

## 环境要求

- Node.js 22 或更高（开发时用的是 24）
- pnpm 10
- PostgreSQL（开发时用的是 18）
- Redis 7 或更高（开发时用的是 8）

## 快速开始

1. 安装依赖：

   ```bash
   pnpm install
   ```

2. 在 PostgreSQL 里建一个角色和数据库（名字和密码可以自己定）：

   ```sql
   CREATE ROLE mmo LOGIN PASSWORD '换成你的密码';
   CREATE DATABASE mmo OWNER mmo;
   ```

3. 把 `packages/server/.env.example` 复制成 `packages/server/.env`，填上自己的连接信息：

   ```bash
   cp packages/server/.env.example packages/server/.env
   ```

   表结构不用手动建，服务器启动时会自动执行 `packages/server/migrations/` 里的 SQL。

4. 启动：

   ```bash
   pnpm dev
   ```

   这会同时启动游戏服务器（端口 8080）和客户端开发服务器（端口 5173）。

5. 用两个浏览器窗口打开 <http://localhost:5173>，各注册一个账号，就能看到对方。同一个浏览器的两个标签页共用登录状态，要测试两个账号请用无痕窗口或另一个浏览器。

## 常用命令

都在仓库根目录执行。

| 命令 | 作用 |
|---|---|
| `pnpm dev` | 同时启动服务器和客户端，改代码后自动重启或刷新 |
| `pnpm dev:server` / `pnpm dev:client` | 只启动其中一个 |
| `pnpm start` | 启动服务器，不监听文件变化 |
| `pnpm build` | 构建客户端，产物在 `packages/client/dist` |
| `pnpm test` | 运行单元测试（不需要数据库和 Redis） |
| `pnpm typecheck` | 三个包的类型检查 |
| `pnpm bots` | 机器人压测，见下文 |

## 配置

服务器从环境变量读配置，本地开发时会先加载 `packages/server/.env`；已经存在的环境变量优先。

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `DATABASE_URL` | 是 | | PostgreSQL 连接串 |
| `REDIS_URL` | 是 | | Redis 连接串 |
| `PORT` | 否 | `8080` | 服务器监听的端口 |
| `HOST` | 否 | 所有网卡 | 服务器监听的地址。前面有反向代理时设成 `::1` 或 `127.0.0.1` |
| `STATIC_DIR` | 否 | | 构建好的客户端目录。设置后服务器同时提供页面；开发时页面由 Vite 提供，不用设置 |
| `MAP_SEED` | 否 | `20261127` | 地图种子。换种子后，存档位置落在障碍物里的角色会重新随机出生 |
| `MAX_PLAYERS` | 否 | `2000` | 同时在线人数上限 |

同步频率、地图大小、移动速度、血量、伤害、怪物数量、掉落概率、商人的位置等游戏参数在 `packages/shared/src/constants.ts`，物品的定义和价格在 `packages/shared/src/items.ts`。

## 工作原理

```
浏览器 ──POST /api/register、/api/login──▶ 服务器 ──▶ PostgreSQL（账号）
        ◀────────── 会话令牌 ──────────             ──▶ Redis（会话）

浏览器 ──WebSocket /ws：join(令牌)、moveTo、target、use、equip、unequip、buy、sell──▶ 服务器（每秒 20 次模拟）
        ◀── welcome、inv、enter、leave、snap、hit、heal、weapon ──
```

- **服务器说了算**。客户端只提交“想去哪”“想打谁”“想用什么”“想拿哪件武器”和“想买卖什么”，寻路、位置、伤害、血量、掉落、拾取、背包、装备和买卖都由服务器计算，客户端改不了自己的位置、血量、物品、金币和攻击力。
- **追击由客户端驱动**。选中怪物后，是客户端不断发 `moveTo` 把角色带到怪物旁边；服务器不替玩家走路，只在“目标活着、玩家站定、距离够近、中间没有墙、冷却结束”时结算伤害。这样战斗中的移动和普通的点击移动走的是同一套预测和校验。
- **怪物和玩家是同一种实体**。它们共用视野、`enter`、`leave` 和快照，血量和死亡状态放在快照里；`hit` 消息只用来播放动作和伤害数字，丢了也不影响血量。玩家复活就是“离开再进入”，没有专门的传送消息。
- **没有物理引擎，角色之间不挡路**。墙是靠寻路绕开的：路线算出来就不会穿墙，走的时候不再做碰撞检测。玩家、怪物和商人可以互相穿过去，这样窄路口不会被人堵死，算好的路线也不会因为别人走动而失效。怪物之间只有“软分离”：离得太近的由服务器慢慢推开，站着打的只绕着目标转、离目标的距离不变，地方不够时仍然会重叠。玩家不参与，所以不影响客户端的本地预测。
- **地上的物品是第三种实体**。它和玩家、怪物共用视野、`enter` 和 `leave`，但不会动，所以不放进快照。拾取没有专门的请求：服务器每个 tick 检查每个活着的玩家脚边有没有能捡的东西，捡到了就把物品从视野里移走，并把整个背包（`inv`）发给这个玩家。
- **手里的武器不算在背包里**。装备是把一件武器从背包挪到手上，卸下是挪回去，`inv` 里同时带着背包和手里的武器。别的玩家通过 `enter` 知道一个人进入视野时拿着什么，之后每次更换由 `weapon` 消息通知；它不像 `hit` 那样可以丢，丢了别人看到的武器就一直是错的。
- **商人不是实体**。他不会动，位置只和地图大小有关，客户端和服务器各自算出来，不用下发，也不进视野和快照。走到他跟前是客户端发的普通 `moveTo`；服务器只在收到 `buy`、`sell` 时检查“活着、离商人够近、金币够、背包放得下”，成了就发一次 `inv`，不成什么也不发。价格和这些规则在 `shared` 里，客户端用同一份规则决定按钮能不能点。
- **声音只是客户端的反馈**。没有为它加任何消息：攻击和挨打的声音跟着 `hit`，喝药水、捡东西、买卖的声音靠比较前后两次的背包得出，倒下和复活看快照里的状态。声效是用 Web Audio 在浏览器里合成的（几层波形和噪声），没有音频文件。浏览器要等用户点过或者按过键才允许出声，所以音频设备是在登录页上第一次操作时打开的。
- **地图不用下发**。地图由种子确定性生成，服务器只告诉客户端种子，两边用同一份代码算出同一张地图。
- **预测和纠正**。客户端用和服务器相同的寻路、移动代码先走，服务器的位置偏离预测轨迹太远时改为跟随服务器。
- **存档不阻塞游戏循环**。位置、血量和背包的变化先记在内存里，再批量写进数据库；写失败时保留到下次重试。背包和位置、血量存在同一行里，一次写入要么都成功要么都不成功。

开发时客户端通过 Vite 把 `/ws` 和 `/api` 代理到游戏服务器，所以浏览器始终只访问同一个地址。

## 机器人压测

服务器运行时执行：

```bash
pnpm bots --count 200 --duration 30
```

脚本会让 N 个机器人登录并在地图上随机走动，附近有怪物时上去打，地上有东西就去捡，血量低于一半时喝药水，捡到武器就拿在手里，离商人不远时去卖掉多余的武器、买药水。每 5 秒报告在线数、视野内的实体数和掉落物数、每个机器人收到的快照数和流量，以及累计的命中、击杀、死亡、拾取、喝药水、装备武器和买卖的次数，结束时打印服务器的统计。

- 机器人的账号是“机器人1”“机器人2”……，第一次运行时自动注册。服务端故意把密码哈希算得慢，200 个账号登录大约要十几秒，登录完才开始计时。
- 这些账号用的是公开的默认密码，只适合本地。对着公开的服务器跑时用 `--password` 换一个。
- `--url` 可以指定别的服务器地址，`--duration 0` 表示一直运行到按 Ctrl+C，`--peaceful` 让机器人只走路、不主动打怪。
- 机器人很多时会把怪物打光，而且几乎不会死，也用不着喝药水，每个机器人分到的金币也不够买东西。想看死亡、复活、喝药水和买卖，用很少的机器人（比如 30 个跑一分钟），或者自己进游戏试。

服务器运行时也可以直接访问 <http://localhost:8080/stats> 看在线人数、活着的怪物数、地上的物品数、命中次数、累计掉落、拾取和买卖的数量，以及 tick 耗时。

## 部署

线上只需要一个进程：设置了 `STATIC_DIR` 之后，游戏服务器除了 `/ws` 和 `/api`，也提供构建好的客户端页面，不需要另外的静态文件服务器。

在要部署的机器上，用 root 在仓库根目录执行：

```bash
deploy/deploy.sh          # 部署当前的 HEAD
deploy/deploy.sh a1b2c3d  # 部署指定的提交
```

脚本只部署已经提交的代码，做这些事：

1. 把那个提交导出到 `/opt/renrengame/releases/` 下的新目录，和开发目录分开。
2. 在新目录里安装依赖、跑类型检查和单测、构建客户端。任何一步失败都不会影响正在运行的版本。
3. 把 `/opt/renrengame/current` 指向新目录，重启 systemd 服务 `renrengame`。
4. 访问 `/stats` 确认服务正常；不正常就切回上一个版本。

第一次运行时脚本会创建：

- `/etc/renrengame/env`：线上的配置（数据库和 Redis 的连接信息、端口、监听地址），只有 root 能读。数据库连接信息取自 `packages/server/.env`，端口默认 5173，只监听本机。要改配置就改这个文件，然后重启服务。
- `/etc/systemd/system/renrengame.service`：服务开机自启，崩溃后自动重启，用一个没有权限的临时系统用户运行。

常用的运维命令：

```bash
systemctl status renrengame      # 运行状态
journalctl -u renrengame -f      # 看日志
systemctl restart renrengame     # 重启（改了 /etc/renrengame/env 之后）
```

重启服务（包括每次部署）时，在线的玩家会断线，位置、血量和背包会先保存；怪物全部重新生成，地上还没捡的物品会消失。

**需要注意的**

- 服务只监听本机，没有自带 HTTPS。它前面必须有一个提供 HTTPS 的代理把请求转进来，否则密码和会话令牌是明文传输的。
- 开发和线上不要连同一个数据库：开发版本启动时会执行还没上线的数据库迁移，同一个账号也可能同时在两边在线。开发时把 `packages/server/.env` 指向另一个库，或者同一个库里另一个 schema（在连接串后面加 `?options=-c%20search_path%3Ddev`），Redis 用另一个编号的库（`redis://localhost:6379/1`）。
- 注册接口没有频率限制，也没有修改密码和找回密码。
- 只有一个服务器进程，所有玩家都在这一个进程里。
- 战斗中直接关掉页面，角色会带着当时的血量立刻下线，可以用来逃跑。

## 素材

`packages/client/public/models/` 里的模型都是用 [Quaternius](https://quaternius.com) 的免费素材包加工出来的：人物是 `human_male.glb` 和 `human_female.glb`，物品是 `item_gold.glb`、`item_potion.glb` 和 `item_sword.glb`（剑在地上和拿在手里用的是同一个模型）。

| 素材包 | 用到的内容 | 授权 |
| --- | --- | --- |
| [Universal Base Characters（Standard）](https://quaternius.itch.io/universal-base-characters) | 男女人物的身体、眼睛、眉毛、头发和皮肤贴图 | CC0 1.0 |
| [Universal Animation Library（Standard）](https://quaternius.itch.io/universal-animation-library) | 待机、跑步、两种出拳、持剑站立、挥剑、倒地这七个动作 | CC0 1.0 |
| [Fantasy Props MegaKit（Standard）](https://quaternius.itch.io/fantasy-props-megakit) | 一堆金币（`Coin_Pile`）、一瓶红色药水（`Potion_2`）和一把青铜剑（`Sword_Bronze`）的模型 | CC0 1.0 |

授权以压缩包里的 `License_Standard.txt` 和 `License.txt` 为准（2026-11-27 下载的版本写的都是 CC0 1.0 Universal，可以随意使用和修改，不要求署名）。

人物的加工由 `tools/models/build.mjs` 完成，它做了这些事：

- 原始人物只穿内衣。脚本按身体部位把模型分成皮肤、上衣、裤子、鞋四块，衣服是纯色的，游戏里按角色换色。
- 把头发挂到头部的骨头上，把动作库里的动作换算到人物自己的骨架上。
- 在右手的骨头下面加一个叫 `Weapon_R` 的空节点，位置在握拳的手心，方向顺着手里握的东西。客户端把武器模型挂在这个节点下面，武器就跟着手动。
- 贴图缩小并转成 WebP，去掉用不到的数据。两个文件一共约 1.4 MB。

怪物用的是男性模型，只是换了颜色、去掉了头发。

物品的加工由 `tools/models/build-items.mjs` 完成。这些道具的颜色存在顶点上，贴图只是一层磨损的细节，物品在游戏里很小，看不出来，所以脚本去掉了贴图，三个文件一共不到 100 KB。原始模型是真实大小（一堆金币只有 20 厘米宽），放大和提亮是客户端加载时做的（`packages/client/src/drops.ts`）；剑拿在手里时的大小、握在剑柄的哪个位置也在那里定。

想换发型、换动作、调整衣服的范围，或者换别的道具，改脚本后重新生成：

```bash
# 1. 从上面的页面下载 Standard 版压缩包，各自解压到同一个目录下以压缩包名字命名的文件夹里，例如
#    ~/quaternius/Universal Base Characters[Standard]/
#    ~/quaternius/Universal Animation Library[Standard]/
#    ~/quaternius/Fantasy Props MegaKit[Standard]/
# 2. 生成模型（输出到 packages/client/public/models/）
cd tools/models
npm install --no-package-lock
node build.mjs ~/quaternius         # 人物，只需要前两个素材包
node build-items.mjs ~/quaternius   # 物品，只需要第三个素材包
```

`tools/models` 不在 pnpm 工作区里，平时开发和部署都不需要安装它的依赖。

声效不是素材：仓库里没有音频文件，每个声音都是 `packages/client/src/synth.ts` 里用正弦波、三角波、锯齿波和滤过的噪声叠出来的，在页面上第一次点击或按键时由浏览器算好。想调某个声音，改那个文件里对应的那几行参数；每种声音播放时的音量在 `packages/client/src/sound.ts`。
