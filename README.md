# renrengame

一个 2.5D 网页多人在线游戏（MMO）的原型：浏览器里用 3D 模型加固定斜俯视角渲染，所有玩家连到同一个权威服务器，在同一张大地图上移动并互相看到。

目前只有“登录、进入世界、点击移动、看到附近的玩家”这一条主线，没有战斗、物品、聊天等玩法。

## 已有的功能

- **画面**：Three.js（WebGL 2）渲染，固定斜俯视角镜头跟随角色，带骨骼动画的角色模型和头顶名字。
- **移动**：点击地面移动，按住可以连续移动，滚轮缩放。服务端寻路并绕开障碍物。
- **同步**：服务器每秒模拟 20 次、下发 10 次快照；自己的角色本地预测，其他玩家用快照插值。
- **视野**：256×256 的地图按 32×32 分格，每个玩家只收到自己所在格和周围 8 格内的实体。
- **账号**：注册、登录，7 天内免密码进入；同一账号在别处登录时旧连接被顶下线。
- **存档**：角色位置在下线时、每 30 秒和服务器关闭时写进数据库。

## 技术栈

| 部分 | 用的东西 |
|---|---|
| 客户端 | TypeScript、Three.js、Vite |
| 服务器 | TypeScript、Node.js、`ws`，用 `tsx` 直接运行 |
| 存储 | PostgreSQL（账号、角色）、Redis（登录会话、登录尝试次数） |
| 工程 | pnpm workspaces、Vitest |

## 环境要求

- Node.js 22 或更高（开发时用的是 24）
- pnpm 10
- PostgreSQL（开发时用的是 18）
- Redis 7 或更高（开发时用的是 8）

## 快速开始

1. 安装依赖：

   ```bash
   pnpm install
   ```

2. 在 PostgreSQL 里建一个角色和数据库（名字和密码可以自己定）：

   ```sql
   CREATE ROLE mmo LOGIN PASSWORD '换成你的密码';
   CREATE DATABASE mmo OWNER mmo;
   ```

3. 把 `packages/server/.env.example` 复制成 `packages/server/.env`，填上自己的连接信息：

   ```bash
   cp packages/server/.env.example packages/server/.env
   ```

   表结构不用手动建，服务器启动时会自动执行 `packages/server/migrations/` 里的 SQL。

4. 启动：

   ```bash
   pnpm dev
   ```

   这会同时启动游戏服务器（端口 8080）和客户端开发服务器（端口 5173）。

5. 用两个浏览器窗口打开 <http://localhost:5173>，各注册一个账号，就能看到对方。同一个浏览器的两个标签页共用登录状态，要测试两个账号请用无痕窗口或另一个浏览器。

## 常用命令

都在仓库根目录执行。

| 命令 | 作用 |
|---|---|
| `pnpm dev` | 同时启动服务器和客户端，改代码后自动重启或刷新 |
| `pnpm dev:server` / `pnpm dev:client` | 只启动其中一个 |
| `pnpm start` | 启动服务器，不监听文件变化 |
| `pnpm build` | 构建客户端，产物在 `packages/client/dist` |
| `pnpm test` | 运行单元测试（不需要数据库和 Redis） |
| `pnpm typecheck` | 三个包的类型检查 |
| `pnpm bots` | 机器人压测，见下文 |

## 配置

服务器从环境变量读配置，本地开发时会先加载 `packages/server/.env`；已经存在的环境变量优先。

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `DATABASE_URL` | 是 | | PostgreSQL 连接串 |
| `REDIS_URL` | 是 | | Redis 连接串 |
| `PORT` | 否 | `8080` | 服务器监听的端口 |
| `MAP_SEED` | 否 | `20261127` | 地图种子。换种子后，存档位置落在障碍物里的角色会重新随机出生 |
| `MAX_PLAYERS` | 否 | `2000` | 同时在线人数上限 |

同步频率、地图大小、移动速度等游戏参数在 `packages/shared/src/constants.ts`。

## 目录结构

```
packages/
  shared/   客户端和服务器共用的代码
    src/      协议、常量、地图生成、A* 寻路、移动、账号校验规则
  server/   游戏服务器
    src/      入口和主循环、世界模拟、AOI、账号与会话、角色存档
    migrations/  数据库表结构
    scripts/  机器人压测脚本
  client/   浏览器客户端
    src/      场景、镜头、输入、网络、本地预测、插值、登录界面
    public/   角色模型
```

## 工作原理

```
浏览器 ──POST /api/register、/api/login──▶ 服务器 ──▶ PostgreSQL（账号）
        ◀────────── 会话令牌 ──────────             ──▶ Redis（会话）

浏览器 ──WebSocket /ws：join(令牌)、moveTo──▶ 服务器（每秒 20 次模拟）
        ◀── welcome、enter、leave、snap ──
```

- **服务器说了算**。客户端只提交“想去哪”，寻路和位置都由服务器计算，客户端改不了自己的位置。
- **地图不用下发**。地图由种子确定性生成，服务器只告诉客户端种子，两边用同一份代码算出同一张地图。
- **预测和纠正**。客户端用和服务器相同的寻路、移动代码先走，服务器的位置偏离预测轨迹太远时改为跟随服务器。
- **存档不阻塞游戏循环**。位置变化先记在内存里，再批量写进数据库；写失败时保留到下次重试。

开发时客户端通过 Vite 把 `/ws` 和 `/api` 代理到游戏服务器，所以浏览器始终只访问同一个地址。

## 机器人压测

服务器运行时执行：

```bash
pnpm bots --count 200 --duration 30
```

脚本会让 N 个机器人登录并在地图上随机走动，每 5 秒报告在线数、视野内实体数、每个机器人收到的快照数和流量，结束时打印服务器的统计。

- 机器人的账号是“机器人1”“机器人2”……，第一次运行时自动注册。服务端故意把密码哈希算得慢，200 个账号登录大约要十几秒，登录完才开始计时。
- 这些账号用的是公开的默认密码，只适合本地。对着公开的服务器跑时用 `--password` 换一个。
- `--url` 可以指定别的服务器地址，`--duration 0` 表示一直运行到按 Ctrl+C。

服务器运行时也可以直接访问 <http://localhost:8080/stats> 看在线人数和 tick 耗时。

## 部署时要注意的

这是原型，还没有为公开上线做准备：

- 客户端连的是和页面同源的 `/ws` 和 `/api`。部署时需要一个反向代理，把 `packages/client/dist` 作为静态文件提供，并把这两个路径转发给游戏服务器。
- 必须走 HTTPS，否则密码和会话令牌是明文传输的。
- 注册接口没有频率限制，也没有修改密码和找回密码。
- 只有一个服务器进程，所有玩家都在这一个进程里。
