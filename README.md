# renrengame

一个 2.5D 网页多人在线游戏（MMO）的原型：浏览器里用 3D 模型加固定斜俯视角渲染，所有玩家连到同一个权威服务器，在同一张大地图上移动、打怪并互相看到。

目前有“登录、进入世界、点击移动、看到附近的玩家、打怪、死亡复活”这一条主线，没有玩家对战、经验等级、掉落和物品、技能、聊天等玩法。

## 已有的功能

- **画面**：Three.js（WebGL 2）渲染，固定斜俯视角镜头跟随角色，带骨骼动画的角色模型，头顶有名字和血条。
- **移动**：点击地面移动，按住可以连续移动，滚轮缩放。服务端寻路并绕开障碍物。
- **战斗**：点击怪物后角色自己走过去，站定后自动攻击，直到怪物死亡或者点了地面。命中时有出拳动作、受击闪烁和伤害数字。
- **怪物**：地图上有 120 只怪物。玩家走近或者打了它，它会追上来攻击；被带离出生位置太远时放弃，回满血走回去，回去的路上不受伤害；死后 20 秒在原地重生。
- **安全区**：出生点周围半径 14 的范围（地上有一圈浅色的线）。怪物不会进去，也不会攻击里面的玩家。
- **死亡和回血**：血量归零后倒地，5 秒后在出生点满血复活。6 秒没有打人也没有挨打，开始慢慢回血。
- **同步**：服务器每秒模拟 20 次、下发 10 次快照；自己的角色本地预测，其他玩家用快照插值。
- **视野**：256×256 的地图按 32×32 分格，每个玩家只收到自己所在格和周围 8 格内的实体。
- **账号**：注册、登录，7 天内免密码进入；同一账号在别处登录时旧连接被顶下线。
- **存档**：角色的位置和血量在下线时、每 30 秒和服务器关闭时写进数据库。死亡状态下线的角色，下次上线时在出生点满血复活。

## 技术栈

| 部分 | 用的东西 |
|---|---|
| 客户端 | TypeScript、Three.js、Vite |
| 服务器 | TypeScript、Node.js、`ws`，用 `tsx` 直接运行 |
| 存储 | PostgreSQL（账号、角色）、Redis（登录会话、登录尝试次数） |
| 工程 | pnpm workspaces、Vitest |

## 环境要求

- Node.js 22 或更高（开发时用的是 24）
- pnpm 10
- PostgreSQL（开发时用的是 18）
- Redis 7 或更高（开发时用的是 8）

## 快速开始

1. 安装依赖：

   ```bash
   pnpm install
   ```

2. 在 PostgreSQL 里建一个角色和数据库（名字和密码可以自己定）：

   ```sql
   CREATE ROLE mmo LOGIN PASSWORD '换成你的密码';
   CREATE DATABASE mmo OWNER mmo;
   ```

3. 把 `packages/server/.env.example` 复制成 `packages/server/.env`，填上自己的连接信息：

   ```bash
   cp packages/server/.env.example packages/server/.env
   ```

   表结构不用手动建，服务器启动时会自动执行 `packages/server/migrations/` 里的 SQL。

4. 启动：

   ```bash
   pnpm dev
   ```

   这会同时启动游戏服务器（端口 8080）和客户端开发服务器（端口 5173）。

5. 用两个浏览器窗口打开 <http://localhost:5173>，各注册一个账号，就能看到对方。同一个浏览器的两个标签页共用登录状态，要测试两个账号请用无痕窗口或另一个浏览器。

## 常用命令

都在仓库根目录执行。

| 命令 | 作用 |
|---|---|
| `pnpm dev` | 同时启动服务器和客户端，改代码后自动重启或刷新 |
| `pnpm dev:server` / `pnpm dev:client` | 只启动其中一个 |
| `pnpm start` | 启动服务器，不监听文件变化 |
| `pnpm build` | 构建客户端，产物在 `packages/client/dist` |
| `pnpm test` | 运行单元测试（不需要数据库和 Redis） |
| `pnpm typecheck` | 三个包的类型检查 |
| `pnpm bots` | 机器人压测，见下文 |

## 配置

服务器从环境变量读配置，本地开发时会先加载 `packages/server/.env`；已经存在的环境变量优先。

| 变量 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| `DATABASE_URL` | 是 | | PostgreSQL 连接串 |
| `REDIS_URL` | 是 | | Redis 连接串 |
| `PORT` | 否 | `8080` | 服务器监听的端口 |
| `HOST` | 否 | 所有网卡 | 服务器监听的地址。前面有反向代理时设成 `::1` 或 `127.0.0.1` |
| `STATIC_DIR` | 否 | | 构建好的客户端目录。设置后服务器同时提供页面；开发时页面由 Vite 提供，不用设置 |
| `MAP_SEED` | 否 | `20261127` | 地图种子。换种子后，存档位置落在障碍物里的角色会重新随机出生 |
| `MAX_PLAYERS` | 否 | `2000` | 同时在线人数上限 |

同步频率、地图大小、移动速度、血量、伤害、怪物数量等游戏参数在 `packages/shared/src/constants.ts`。

## 目录结构

```
packages/
  shared/   客户端和服务器共用的代码
    src/      协议、常量、地图生成、A* 寻路、移动、账号校验规则
  server/   游戏服务器
    src/      入口和主循环、世界模拟、怪物 AI、AOI、账号与会话、角色存档
    migrations/  数据库表结构
    scripts/  机器人压测脚本
  client/   浏览器客户端
    src/      场景、镜头、输入、点选和追击、网络、本地预测、插值、登录界面
    public/   角色模型
deploy/     部署脚本
```

## 工作原理

```
浏览器 ──POST /api/register、/api/login──▶ 服务器 ──▶ PostgreSQL（账号）
        ◀────────── 会话令牌 ──────────             ──▶ Redis（会话）

浏览器 ──WebSocket /ws：join(令牌)、moveTo、target──▶ 服务器（每秒 20 次模拟）
        ◀── welcome、enter、leave、snap、hit ──
```

- **服务器说了算**。客户端只提交“想去哪”和“想打谁”，寻路、位置、伤害和血量都由服务器计算，客户端改不了自己的位置和血量。
- **追击由客户端驱动**。选中怪物后，是客户端不断发 `moveTo` 把角色带到怪物旁边；服务器不替玩家走路，只在“目标活着、玩家站定、距离够近、中间没有墙、冷却结束”时结算伤害。这样战斗中的移动和普通的点击移动走的是同一套预测和校验。
- **怪物和玩家是同一种实体**。它们共用视野、`enter`、`leave` 和快照，血量和死亡状态放在快照里；`hit` 消息只用来播放动作和伤害数字，丢了也不影响血量。玩家复活就是“离开再进入”，没有专门的传送消息。
- **地图不用下发**。地图由种子确定性生成，服务器只告诉客户端种子，两边用同一份代码算出同一张地图。
- **预测和纠正**。客户端用和服务器相同的寻路、移动代码先走，服务器的位置偏离预测轨迹太远时改为跟随服务器。
- **存档不阻塞游戏循环**。位置和血量的变化先记在内存里，再批量写进数据库；写失败时保留到下次重试。

开发时客户端通过 Vite 把 `/ws` 和 `/api` 代理到游戏服务器，所以浏览器始终只访问同一个地址。

## 机器人压测

服务器运行时执行：

```bash
pnpm bots --count 200 --duration 30
```

脚本会让 N 个机器人登录并在地图上随机走动，附近有怪物时上去打。每 5 秒报告在线数、视野内实体数、每个机器人收到的快照数和流量，以及累计的命中、击杀和死亡次数，结束时打印服务器的统计。

- 机器人的账号是“机器人1”“机器人2”……，第一次运行时自动注册。服务端故意把密码哈希算得慢，200 个账号登录大约要十几秒，登录完才开始计时。
- 这些账号用的是公开的默认密码，只适合本地。对着公开的服务器跑时用 `--password` 换一个。
- `--url` 可以指定别的服务器地址，`--duration 0` 表示一直运行到按 Ctrl+C，`--peaceful` 让机器人只走路、不主动打怪。
- 机器人很多时会把怪物打光，而且几乎不会死。想看死亡和复活，用很少的机器人，或者自己进游戏站在怪物旁边不还手。

服务器运行时也可以直接访问 <http://localhost:8080/stats> 看在线人数、活着的怪物数、命中次数和 tick 耗时。

## 部署

线上只需要一个进程：设置了 `STATIC_DIR` 之后，游戏服务器除了 `/ws` 和 `/api`，也提供构建好的客户端页面，不需要另外的静态文件服务器。

在要部署的机器上，用 root 在仓库根目录执行：

```bash
deploy/deploy.sh          # 部署当前的 HEAD
deploy/deploy.sh a1b2c3d  # 部署指定的提交
```

脚本只部署已经提交的代码，做这些事：

1. 把那个提交导出到 `/opt/renrengame/releases/` 下的新目录，和开发目录分开。
2. 在新目录里安装依赖、跑类型检查和单测、构建客户端。任何一步失败都不会影响正在运行的版本。
3. 把 `/opt/renrengame/current` 指向新目录，重启 systemd 服务 `renrengame`。
4. 访问 `/stats` 确认服务正常；不正常就切回上一个版本。

第一次运行时脚本会创建：

- `/etc/renrengame/env`：线上的配置（数据库和 Redis 的连接信息、端口、监听地址），只有 root 能读。数据库连接信息取自 `packages/server/.env`，端口默认 5173，只监听本机。要改配置就改这个文件，然后重启服务。
- `/etc/systemd/system/renrengame.service`：服务开机自启，崩溃后自动重启，用一个没有权限的临时系统用户运行。

常用的运维命令：

```bash
systemctl status renrengame      # 运行状态
journalctl -u renrengame -f      # 看日志
systemctl restart renrengame     # 重启（改了 /etc/renrengame/env 之后）
```

重启服务（包括每次部署）时，在线的玩家会断线，位置和血量会先保存；怪物全部重新生成。

**需要注意的**

- 服务只监听本机，没有自带 HTTPS。它前面必须有一个提供 HTTPS 的代理把请求转进来，否则密码和会话令牌是明文传输的。
- 开发和线上不要连同一个数据库：开发版本启动时会执行还没上线的数据库迁移，同一个账号也可能同时在两边在线。开发时把 `packages/server/.env` 指向另一个库。
- 注册接口没有频率限制，也没有修改密码和找回密码。
- 只有一个服务器进程，所有玩家都在这一个进程里。
- 战斗中直接关掉页面，角色会带着当时的血量立刻下线，可以用来逃跑。
